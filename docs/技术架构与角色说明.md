# 房产看房预约系统 - 技术架构与角色说明

## 一、系统概述

本系统是一个面向房产中介的**看房预约管理平台**，主要功能包括：
- 中介管理客户分组、房源、预约日程
- 客户通过分享链接匿名查看自己的看房日程与房源详情
- 支持买房/租房、出售/出租双维度业务
- 房源信息从 Property Guru / Property Group 等平台自动抓取

---

## 二、角色体系

### 2.1 用户角色（profiles.role）

| 角色 | 英文 | 说明 | 路由入口 |
|------|------|------|----------|
| **中介** | `agent` | 房产经纪人，创建和管理客户、房源、预约 | `/home/agent` |
| **客户** | `client` | 购房/租房客户，通过分享链接查看或使用自己的看房中心 | `/home/user` |

### 2.2 管理员标志（profiles 表字段）

| 字段 | 类型 | 说明 |
|------|------|------|
| `is_admin` | boolean | 是否管理员，可访问 `/admin` 页面，查看邀请关系、抓取失败等 |
| `is_super_admin` | boolean | 超级管理员，拥有更高权限（如管理 scrape_failures 等） |

> 需在数据库中手动设置：`update profiles set is_admin = true where id = '用户uuid';`

### 2.3 客户分组类型（customer_groups.group_type）

客户分组有两种用途：

| 类型 | 英文 | 说明 | intent 取值 |
|------|------|------|-------------|
| **买家/租客** | `client` | 代表一组看房的客户（如一家人），关联多个待看房源 | `buy` / `rent` |
| **出售/出租房源** | `listing` | 代表中介自己的待售/待租房源，一个分组对应一套房 | `sale` / `rent` |

### 2.4 预约中的角色（appointments.party_role）

创建预约时，可标注预约方角色：

| 角色 | 英文 | 说明 |
|------|------|------|
| 买家 | `buyer` | 买房客户，必须关联 customer_group |
| 租客 | `tenant` | 租房客户，必须关联 customer_group |
| 卖家 | `seller` | 卖方，无需 customer_group，可选填 customer_info |
| 房东 | `landlord` | 出租方，无需 customer_group，可选填 customer_info |

## 四、权限与访问控制

### 4.1 Row Level Security（RLS）

- **profiles**：用户只能读写自己的 profile
- **customer_groups**：中介只能操作自己的分组
- **properties**：中介只能操作自己的房源
- **appointments / notes**：通过 property → agent_id 校验，仅中介管理自己下的数据
- **pending_appointments**：同上
- **agent_feedback**：已登录用户可读、可插入（可匿名），投票只能操作自己的
- **scrape_failures**：无 permissive 策略，仅通过 admin RPC 或 service role 访问

### 4.2 客户视图（匿名访问）

客户通过分享链接 `/view/:token` 访问，**无需登录**：

- 使用 **share_token**：只读，可查看日程、房源、中介备注、客户备注
- 使用 **share_token_edit**：可编辑客户自己的备注（预约备注、待预约备注）

校验逻辑在 RPC `get_client_view(p_share_token)` 中：
- 通过 token 查找 customer_group
- 返回 `can_edit` 表示当前 token 是否具有编辑权（edit token 或已登录中介）

## 五、技术栈与架构

### 5.1 前端

- **React** + **TypeScript**
- **Ant Design** + 自定义主题
- **react-i18next** 多语言
- **TanStack Query** 数据请求
- **Supabase JS Client** 直接连接数据库（含 RLS）

### 5.2 后端

- **Supabase**
  - **Auth**：邮箱/密码注册登录
  - **PostgreSQL**：所有业务表
  - **RLS**：行级安全
  - **RPC**：`get_client_view`、`save_client_appointment_note`、`save_client_pending_note`、`check_phone_available`、`admin_get_invite_relations`、`admin_get_scrape_failures` 等

- **FastAPI**（`web/backend/main.py`）
  - 房源抓取 API（Playwright）
  - 限流、防重复抓取
  - 异步后台任务写入 Supabase（需 `SUPABASE_SERVICE_ROLE_KEY`）

### 5.3 抓取 API

| 接口 | 说明 |
|------|------|
| `POST /api/scrape-property` | 同步抓取，用于刷新按钮 |
| `POST /api/trigger-scrape` | 异步触发，立即返回 202，后台更新数据库 |
| `POST /api/batch-scrape-properties` | 批量添加待预约 + 后台抓取 |
| `POST /api/add-agent-listing` | 添加中介自售/出租房源，立即返回 202，爬虫后台异步执行 |
| `POST /api/scrape-site-plan` | 从 99.co 抓取公寓 site plan |

## 六、关键业务流程

### 6.1 注册与邀请

1. 注册时选择角色（agent/client），填写姓名、手机等
2. 可选填邀请码（invited_by_code），关联邀请人
3. 新用户自动生成 `invite_code`，手机号唯一

### 6.2 客户分组与分享

1. 中介创建客户分组（client 或 listing）
2. 系统生成 `share_token`、`share_token_edit`
3. 分享只读链接：`/view/{share_token}`
4. 分享可编辑链接：`/view/{share_token_edit}`

### 6.3 客户视图数据流

1. 客户打开 `/view/:token`
2. 前端调用 `supabase.rpc('get_client_view', { p_share_token: token })`
3. RPC 校验 token，返回 group、appointments、pending_appointments、can_edit
4. 客户编辑备注时调用 `save_client_appointment_note` 或 `save_client_pending_note`（需 edit token 或已登录中介）

### 6.4 房源抓取流程

1. 中介添加房源 URL 或批量添加
2. 后端创建/复用 property，创建 pending_appointment（如有）
3. 后台 Playwright 抓取 Property Guru / Property Group 页面
4. 成功：更新 properties 表
5. 失败：写入 scrape_failures，管理员可查看
